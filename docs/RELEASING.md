## 首次上传范围与验收（历史）

先整理首页与成果入口，清除可发布源码中的私人路径默认值，排除凭据与本机资料，再导出可独立检查的源码包。推理实现、默认调度、实验编号与已归档证据不变；不把文档整理当成新的性能结果。

验收要求：中英文 README 有可执行入口和收益边界；50 份旧证据字节不变；成果生成器检查通过；源码白名单逐文件扫描与哈希检查通过；新目录解压后基础工具回归和离线报告检查通过。正式推理性能不在本轮重跑范围。

## 两种发布范围

| 范围 | 清单／入口 | 用途 |
| --- | --- | --- |
| 完整源码及公开数据 | `docs/github-release-manifest.json`、`tools/prepare_github_release.py` | 首次 GitHub 源码内容准备，保留测试生成物与设计历史 |
| 离线成果包 | [成果发布说明](benchmarks/PUBLISHING.md)、`docs/benchmarks/publication-manifest.json` | 只携带明确列入白名单的报告、证据和分析工具 |

源码白名单只接收根构建／说明／示例文件，以及 `include/`、`src/`、`tests/`、`tools/`、`docs/` 中指定类型的文件。出现未列入白名单但 Git 可见的文件会阻止校验；不会直接把整个工作目录压缩上传。符号链接、超大文件和不允许的类型拒绝发布。

## 本地资料与内容扫描

`agentctl.json`、环境文件、会话历史、`.workbuddy/`、同目录 DialogMesh、`build/`、模型／运行时、请求日志和 KV 快照不进入源码包。保留本机配置以便继续开发；不为发布删除使用中的凭据，也不输出匹配到的秘密值。

源码中的端点只允许通用回环示例、测试夹具和明确的占位符；示例 key 为空。文档／代码中的私人主目录、私人模型默认目录、私网服务地址、URL 内嵌凭据、常见 token／私钥格式及可疑非空 key 赋值会被检查；PNG 的文本、压缩文本、ICC／Exif／XMP 元数据也纳入模式检查。报告只给出文件、行号和规则名。通用回环地址不能据此当成用户私人服务地址。

静态模式检查不能证明不存在任何形式的秘密；本次发布边界是白名单里的公开工作树，忽略目录和本地配置不转成公开数据。源码包不携带 `.git`，不复制内部检查点或历史对象。后续若从已有历史的分支发布，还需单独检查将要推送的提交历史。

## 可重复执行的准备命令

```sh
# 文档／展示变更后先重建成果清单。
python3 tools/build_benchmark_report.py
python3 tools/build_benchmark_report.py --check

# 生成源码哈希清单，检查 Git 可见范围与内容，然后确定性导出。
python3 tools/prepare_github_release.py
python3 tools/prepare_github_release.py --check \
  --export build/cxf-github-source-20261101-initial-publish.zip
```

导出前会再次检查所有哈希。校验本身不是上传授权；本轮上传依据仓库所有者 2026-11-01 的明确指令。首次提交应使用这个已检查的文件范围，避免直接复制工作目录或添加忽略资料。任何后续源码／文档变更都会使相应清单过期，需要重建后再检查。

解压到新的空目录后运行：

```sh
make test
python3 tools/build_benchmark_report.py --check
python3 tools/prepare_github_release.py --check
python3 tests/test_release_guard.py
```

原生模型验收另按[项目首页](../README.zh-CN.md)传匹配 SDK、运行时与模型。三个原生脚本的默认依赖位置现为仓库内 `local-model/`；以前只在本机存在的默认路径不再发布，显式参数接口不变。没有重新测量旧实验，旧源码哈希继续指向各自测量版本。
