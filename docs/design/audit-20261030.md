# 设计缺口审计 · 2026-10-30

范围：当前 cxf 本地推理适配及其文档。核对公开／私有头、Native、worker、Stream、构建脚本和已有契约／证据；本轮没有运行新的模型实验。状态入口为 [设计登记](README.md)。

后继更新：独立 D-COST / E13 已实现暖态服务时间估算，按用户要求先于调度；下面仍是本次审计时的缺口记录。G11 的 ETA／派发／保留策略及 G14 的冷启动／跨平台仍未完成，不能用 E13 的预测误差成绩填补它们。

## 结论

已有核心 token/session 契约、聊天模板边界、工具权限与性能口径基本齐备。主要缺口是宿主模块的现行契约散落于大文档、不同 ready 的含义、协调器与旧模块的所有权交接，以及新预热计划尚无接口／状态／容量约束。本轮补设计和入口；需要代码或新数据的问题继续标未完成。

## 保留的已有设计

不重新设计单份 canonical token 池、句柄世代、核心 revision、fork/replace、预算与 logits 恢复；不重写模板语义、权限执行器或工具协议。新协调器通过这些边界接入。内存审计仍分别记录原文、ID、KV、临时对象与 RSS；快照仍严格同 engine／session／revision。

通用并发快照草案 D-OLD-CONC 没有实现，也不成为本轮预热的必需存储层。使用显式源借用不等于引入该草案的通用对象版本系统。

## 后续整理边界

现在只抽出独立契约并建立跳转，不迁移全部历史记录或改写既有性能证据。未来归档旧文档时保留旧锚点／实验编号、替代关系与证据哈希；每次只指定一个主题的当前契约。遗留 `docs/agent.md` 的大范围设计与私人端点等仍属首次公开推送前的独立审查。

本轮验证应包括：设计与当前头／实现的边界核对、链接／锚点、发布白名单、旧 evidence 哈希不变及离线包复核；不把这些检查写作新运行时正确性或性能测试通过。
