# 多行编辑与版本前置条件 v1（D-EDIT）

状态：2026-11-02 实施前冻结，现已实现并验收；E59为工具／开销，E60为真实云模型任务，E61为独立成本探针。默认CLI随显式write注册；不把确定性验收或API延迟当成模型能力／工具成本。

## 范围与基线

新增 `fs.edit`，仅随已有 `--write DIR` 注册，使用同一 WRITE 权限、根目录和 D-DATA 策略。现有 read/list/replace_line/write_apply 的权限不扩大。一次只改已有普通文本文件中的一个唯一、精确字节匹配块；支持多行、空新块删除及无末尾换行。旧块不可空，不创建文件、不做多文件事务、模糊匹配、自动重试或冲突合并。

`fs.read` 回执在 path 后增加 `version=...`，正文与 offset/bytes/total/next 语义不变。版本取实际读取 fd 的 dev/ino/size/mode/uid/gid/nlink/mtime/ctime（含纳秒），读取前后校验稳定才发布。v1 是显式编码的文件元数据，不是内容哈希、认证凭据或跨复制／文件系统的稳定 ID。每页都有自己的版本；页间版本变化应重读。

## 调用与回执

沿用当前工具 schema 的单个字符串 `args`，完整格式为：

```text
relative/path.txt
从fs.read原样复制的版本号
<<<<<<< SEARCH
old block
=======
new block
>>>>>>> REPLACE
```

第一行 path，第二行 version；随后固定开始标记。分隔符分别是 `\n=======\n` 和 `\n>>>>>>> REPLACE`，标记前的一次 LF 仅作协议分隔，不属于旧／新块。末尾允许零或一个 LF，不接受其他尾部。需要在块中包含结尾 LF 时，在标记前再保留一次 LF。正文按字节匹配，不自动改 CRLF、空白或 Unicode；正文出现完整保留分隔符时拒绝，避免解释歧义。保留未替换部分的原始字节和末尾换行。

输入沿用 CLI 单次参数 1KiB 上限；目标与结果文件均最多64KiB，输出预留512B。目标 body 临时堆最多64KiB+1；不新增会话／历史存储。不因该功能提高所有工具的参数上限。

逻辑结果返回 CXF_OK 和 `#edit status=... reason=... matches=N bytes=N version=...`；调用者必须看 status，不能把 handler OK 当成落盘。状态包括 applied、same、conflict、not_found、ambiguous；matches最多计到2，2表示至少两处。conflict原因至少区分stale、busy、changed；已知版本可返回，未知用 `-`，模型遇到冲突必须重读。格式、权限／类型／容量和I/O错误返回非FULL失败，正文不发布，既有文件保持；输出容量不足在任何文件操作前拒绝。

## 所有权、并发与提交边界

部署 root/policy 在同步调用期间借用且不可变；版本不授予权限。沿目录fd验证根内路径和真实inode，拒绝敏感文件／配置别名、符号链接、硬链接、非普通文件和路径越界。输入、现有正文及新正文继续执行秘密内容准入，不在回执中回显正文。

打开目标后取得非阻塞 `flock(LOCK_EX|LOCK_NB)`，持有原fd直到提交／清理结束。与本工具协作的并发写者不会同时提交基于同一旧inode的编辑：忙即conflict；等待前打开的旧fd还须通过最终路径inode／版本校验。读取、计算、写临时文件后，在持有的父目录fd下再次核对当前目标版本。

同目录排他创建0600临时文件；写prefix、新块、suffix，保持普通权限位并fsync；所有提交前失败关闭并删除临时文件，不truncate原文件。临时文件close失败也不提交。最后一次renameat是可见提交点。成功后绝不返回FULL或把后置诊断失败当成“没写入”触发重跑；新的版本若无法取得，applied仍成立、version为-并要求重新读取。父目录崩溃持久化、owner/ACL/xattr保持、恶意同UID目录搬移与文件系统事务不在本轮保证内。

flock是建议锁，外部程序可忽略；外部写者由前后fd stat及最终路径版本尽力检测，最终校验与rename之间仍有竞态，不能称文件系统原子CAS。网络文件系统、Windows原生与WSL挂载盘的锁／权限语义未验收。依据[flock官方man-pages](https://man7.org/linux/man-pages/man2/flock.2.html)；本机行为用真实双进程测试核对。

## 验收与测量

正常：LF/CRLF、多行、中文、空新块、同内容、无末尾LF、唯一匹配和回读；旧版read分页正文不变。冲突：读后原地改写、替换同名文件、权限变化、双进程同版本竞争、外部写入发生于读后／提交前；不得丢失已观察到的新版本。

越权：无write部署不公开／不执行fs.edit、敏感名／实际配置inode／链接／越界／非普通文件／已知秘密。失败不破坏：畸形帧、小输出、超限、OOM及临时创建／短写／fsync／close／rename失败；断言原bytes、mode和无临时残留。确定性故障钩子只编入独立测试构建，不受模型、环境或生产配置控制；实际OS错误和注入错误分开记录。

开销实验用同负载、轮换顺序、独立新运行目录：E58版read对当前版本化read；相同最终文件的旧单行／整文件替换对新多行工具；handler与包含读取的流程分开。版本检查、额外stat／锁／格式处理、fsync成本及负结果单列；不靠关闭默认权限改善成绩。写操作重置和最终bytes验证是否在计时内必须声明，不把不同语义的冲突拒绝当成成功写入加速。

用户另指定真实云端模型：从部署者指定的私有配置选择模型`deepseek-v4-flash-0731`。只发送新建合成工作区；key和端点不写源码、命令行或公开证据。使用既有云外发显式授权和可信回环代理边界，不放宽默认HTTP／文件／命令策略。记录实际工具调用、磁盘产物、独立编译／测试、冲突后的重读及失败，和确定性／性能数据分别归档。

实际配置选中 `deepseek-v4-flash-0731`，上游是用户指定的HTTP网关。测试转发器只在回环监听，API认证仅保存在其内存并发往该配置；CLI仍声明cloud/workspace且保持现有进程隔离。此测试链不提供上游TLS保证，不改变生产HTTP出口的回环限制，也不把普通HTTP描述为TLS。只归档脱敏结果和计数，本机配置与原始请求／响应不进入成果包。

实现后同步当前状态、E59起新证据、报告／CSV／图表注册与发布清单；旧E01–E58证据不可改写。此契约是本功能唯一规范，basic-agent只维护入口与状态。

首轮363条开销记录发现：64KiB成功编辑约多5.6–5.8ms，same约多2.9ms，读取没有稳定回退；这还不能直接归因于版本检查。追加独立探针分开元数据版本格式、建议锁和正文策略扫描（0／1／16登记秘密），不减少检查或改动生产算法。独立阶段中位数不相加反推总耗时；首轮负结果保持原样，新增诊断单独编号。

## 实施与结果（2026-11-02）

入口为 `basic_patch_exec` 与 `basic_file_version`，同BasicFsCfg和既有策略注册fs.edit。normal read现在同样执行读后stat并返回版本；新工具只占64KiB+1临时正文，不新增持久历史。生产没有故障钩子符号／运行时配置；只有独立CXF_EDIT_TEST测试构建支持故障注入。

34项状态／越权／失败保护通过普通与ASan/UBSan，4组真实CLI确定性用例及完整默认回归通过。当前Native14,357-token与8项KV分叉／模板验收通过（其中2项注入流程仍不算模型能力）。初版CLI桩误把message当完整response的失败保留，不修改真实模型回复以取得通过。

E60真实云端DeepSeek Flash三项均通过最终源码逐字节和实际测试核对：正常多行修复；收到过期版本冲突后重读、重新编辑并保留外部注释；只读部署未修改。实际分别5／7／3次API请求，耗时11.159／13.207／5.601s含云／网络／转发，不能当工具开销或通用能力分数。模型协议参考[DeepSeek工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)，测试显式thinking disabled。

E59 363条无SAN记录保留所有负对：1／16／64KiB单行对新工具逐对中位额外77.750／1335.375／5697.750us；多行整写控制为120.000／1454.000／5754.625us；含读流程为88.125／1337.375／5611.500us。大文件整写只比较C handler，不能绕过或冒充CLI的1KiB输入能力。same在64KiB额外2872.750us；读取符号混合，不称提速。
