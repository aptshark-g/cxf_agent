## 阅读与裁决顺序

1. 本登记表确定当前契约在哪里、是否实施。
2. 对应契约决定接口、所有权、失效和验收口径。
3. 适配清单描述当前接线程度，不能替代详细契约。
4. 证据文件描述其实际测量版本；源码变化后不自动变成新版本成绩。
5. 阶段记录、实验设想、聊天记录只提供背景。发现冲突时记录差异并核对代码，不能从不同阶段拼出一个从未实现的版本。

2026-10-30 的 [缺口审计](audit-20261030.md) 逐项列出本轮补齐的文档和仍需实施／验收的问题。

## 文档生命周期

| 状态 | 使用规则 |
| --- | --- |
| 待实现设计 | 可以写拟议接口与验收；必须明确没有运行时／性能交付 |
| 当前契约 | 对应已有实现；新行为先改契约，验收后更新完成状态与证据 |
| 阶段记录 | 保留当时问题、配置、结果及限制；引用新契约，不继续添加新的规范要求 |
| 已取代 | 保留标题／旧锚点和替代链接；不要删除可追溯证据，也不要维护第二份现行规范 |

兼容的澄清直接改当前契约并写变更记录；接口、所有权或结果有效性发生不兼容改变时建立 v2，登记替代关系与迁移方案。不要为每一轮聊天建立新版本。代码路径迁移与文档编号分开，已有 A01–A14 / E01–E12 / L01 保持含义。

每个当前／待实现契约至少包含：状态、范围、基线、所有权、输入与版本、状态变化、取消／关闭、容量、失败行为、兼容性、验收和后续边界。实施前不能留会改变正确性的二选一决策；性能阈值可以明确留待测量。

维护步骤见 [MAINTENANCE](../benchmarks/MAINTENANCE.md)。本次不整理 `docs/agent.md` 等全部历史设计，不重写既有实验数据；它们在未来全仓库文档整理时单独审查。
